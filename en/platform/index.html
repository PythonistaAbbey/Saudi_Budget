How the concept is engineered, what it does and does not do today, and how it would become a secure production platform.

Independent concept — not the official website

This prototype was produced independently and without solicitation to demonstrate a possible future direction. It is not affiliated with, endorsed by, or operated by Budget Saudi / United International Transportation Company. Prices, availability, bookings, customer accounts, corporate data and dashboards are simulated. Public facts are shown with their source and retrieval date (11 November 2026). Imagery is original vector illustration. Showing security and privacy controls here does not mean the prototype is secure or compliant.

Target architecture

API-first, so the frontend never needs a rewrite.

Typed data contracts

UI reads through modules (src/lib, src/data) whose shapes match the PostgreSQL schema in docs/schema.sql. Swapping mock data for API calls is a data-layer change.

Pure pricing engine

Quotes are pure, unit-tested functions — the same logic can run server-side to make prices authoritative.

Bilingual by construction

Locale-prefixed routes, RTL via logical CSS properties, Intl formatting, and a compile-time parity check on shared strings.

Security & privacy by design

Controls, and their honest status

In this prototype Designed, not built Production requirement

Identity & access

  • OIDC sign-in with MFA (e.g. Nafath for Saudi citizens & residents, passkeys for others)
  • Role-based access: customer, fleet admin, driver, finance, CMS editor, administrator
  • Short-lived, HttpOnly, Secure, SameSite session cookies with rotation

Application security (OWASP Top 10)

  • Schema validation on every form (Zod) — mirrored server-side in production
  • Security headers: nosniff, frame-deny, referrer & permissions policy
  • Strict Content-Security-Policy with nonces
  • CSRF protection, rate limiting and bot defence on booking & login
  • Dependency scanning, SAST and authorised penetration testing before launch

Data & privacy (PDPL)

  • No real personal data, payments or ID documents collected
  • Data minimisation: only fields needed for the rental; explicit, withdrawable marketing consent
  • Data residency in-Kingdom, encryption at rest (KMS) and TLS 1.2+ in transit
  • PDPL compliance review, records of processing, DPIA and data-subject request workflow
  • Payments via PCI-DSS certified provider (mada, Apple Pay, cards) — no card data on our servers

Operations

  • Audit log of administrative actions
  • Secrets in a managed vault; no secrets in the repository
  • CI/CD with automated tests, preview environments and signed releases
  • Uploads (e.g. damage photos) scanned, type-checked and stored privately

No security testing of any kind was performed against Budget Saudi's live systems while building this concept.
